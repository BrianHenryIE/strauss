3 * Decides whether a path in a repository is ignored by the `.gitignore` files above it.
4 *
5 * A replacement for `inmarelibero/gitignore-checker` which gives the same answers, including where those differ
6 * from Git's own, so the files Strauss copies do not change. That library re-reads and re-parses every
7 * `.gitignore` above a path, and rebuilds every rule's regex, for each path it is asked about. Here each
8 * `.gitignore` is read and compiled once per repository, and the result of matching a rule against a path
9 * segment is remembered: a project's paths are made of a small number of distinct segments.
10 *
11 * How a path is decided:
12 *
13 * - The `.gitignore` in each directory above the path is consulted, from the repository root down. The first
14 *   which ignores the path decides; a deeper file cannot un-ignore it.
15 * - Within a file, the path is ignored when a rule matches it and no later `!` rule also matches it.
16 * - Rules are matched segment by segment, case-insensitively, against the path from the repository root (even
17 *   for a nested `.gitignore`). `*` matches any run of characters; a leading `/` requires the match to be the
18 *   first segment; a trailing `/` requires it not to be the path's final segment unless the path is a directory.
19 *
20 * @see \BrianHenryIE\Strauss\Pipeline\FileEnumerator::excludeGitFiles()
